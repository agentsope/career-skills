# JD 解剖 · jd-anatomy

一份 JD 看着是一坨,其实有固定骨架。拆开它,才能分清"必须满足"和"锦上添花",并提对关键词。

---

## 1. JD 的五块结构

| 块 | 常见标题 | 看什么 |
|---|---|---|
| **岗位职责** | 工作内容 / 你将做什么 / Responsibilities | 这岗**实际干什么**——判断是否你想做、能做 |
| **任职要求** | 任职资格 / 要求 / Requirements | **门槛**——区分硬性 vs 软性(见下) |
| **加分项** | 优先 / 加分 / Nice to have | 有更好、没有也能投 |
| **公司·团队** | 公司介绍 / 团队 | 规模、阶段、业务——判断靠谱度与发展 |
| **薪资·地点·其他** | 薪资 / 地点 / 汇报对象 | 现实因素;"薪资面议"另见 `jd-subtext.md` |

---

## 2. 硬性 vs 软性(最关键的区分)

用户最需要知道:**哪些不满足就基本没戏,哪些只是加分。**

**硬性门槛(不满足别硬投,或需如实说明):**
- 学历 / 专业:"统招本科及以上""计算机相关专业"——常是简历关机器/HR 初筛的硬卡。
- 经验年限:"3 年以上"——应届投社招岗多半被卡。
- 资格证 / 硬技能:"持 CPA""必须会 SQL"。
- 硬条件:地点、是否接受出差、语言(如"英语可作工作语言")。

**软性 / 可争取:**
- 能力词:"较强的沟通能力""学习能力强"——可用经历证明,不是门槛。
- 加分项:"有…者优先"——锦上添花。

> 判断信号:出现"必须 / 须 / 要求 / 统招 / 及以上 / X 年以上"= 硬;"优先 / 加分 / 熟悉 / 了解 / 有…更佳"= 软。

---

## 3. 关键词提取:频率 × 位置 加权

不是所有词一样重。按两个维度给权重:

- **位置**:出现在**岗位名 / 职责前几条 / 要求第一条**的词,最核心。
- **频率**:**反复出现**的技能 / 能力词,是真需求(如"数据"出现 5 次)。

> 高权重关键词 = 既靠前又反复。这些词要原样回流到简历(交给 `resume-tailor`),机器筛常按字面匹配。

---

## 4. 把它整理成清单(给 Step 3 用)

输出三栏 + 关键词:
- **required(硬性)**:学历/专业/经验/必须技能
- **preferred(加分)**:优先项
- **responsibilities(实际干啥)**:核心职责 2-4 条
- **keywords**:按 freq×position 排好的核心词

> 这份清单直接喂给能力映射(`competency-extraction.md`)。
