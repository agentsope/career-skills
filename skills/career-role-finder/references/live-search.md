# 联网找真实在招 · live-search

具体职位**必须联网实时找**。绝不从记忆里"列"岗位——那些要么过时、要么是编的。本文件讲怎么搜、怎么给真实链接、抓不到怎么办。

> **最高红线:** 列出的每一个公司 / 职位 / 链接,都必须是**这次联网真实搜到、链接可达**的。搜不到对口的 → **如实说**,请用户给平台 / 链接,或先只给方向。**绝不**为了"显得有结果"编一个像样的公司名 + 岗位 + 假 URL。这是本 pack 最容易翻车、也最不可原谅的地方。

---

## 1. 搜索怎么组关键词

`方向 + 身份 + 地点 + 时效`,例:
- "数据分析 实习 北京 2026 牛客"
- "前端 校招 应届 2026 Boss直聘"
- "运营 实习生 上海 实习僧"

身份词:实习 / 校招 / 应届 / 社招;时效词带当前年份 / "最新",避开旧帖。

---

## 2. 去哪搜(按"能不能抓到完整内容"排优先级)

**第一梯队(最能抓到全文,优先抓):**
- **公司官方校招官网** — 如 `jobs.bytedance.com/campus`、`join.qq.com`(腾讯)、`campus.163.com`(网易);JD 最准最新,正文多可直接抓。
- **机构 / 国企 / 交易所 / 高校官网招聘页** — 交易所、银行、研究所、学校就业网;具体岗常能整页读到。
- **聚合页 / 汇总** — 牛客大厂校招汇总贴、GitHub 校招仓(如 `Campus2026`)、应届生求职网 `yingjiesheng.com`、`cn.indeed.com`、卡码投递表;结构化、带官方投递链接、网页可读。

**第二梯队(搜得到、但详情页常反爬):**
- **Boss直聘 / 实习僧** — 适合"看有哪些岗",但**职位详情页常被反爬 / 登录墙挡**,`WebFetch` 抓正文经常失败 → 把链接给用户、或让用户贴回来(见 §4)。

> **每次必搜(默认入口)**:至少过一遍「一个对口的官方校招官网 + GitHub 校招聚合仓 `github.com/namewyf/Campus2026`」——这俩最稳、最全、最可读,是兜底的真实来源。
>
> 打法:`WebSearch` 找候选 → 优先 `WebFetch` 第一梯队的真实职位 / 汇总页拿全文;第二梯队抓不到就别硬抓,转 §4。

---

## 3. 给链接的规矩

每个职位给:
```
公司 · 岗位 · 真实链接 · "截至 <抓取日期> 在招,投递前自行确认"
```
- 链接必须是**真搜到**的;不确定真假的不放。
- **标抓取时间**——职位随时下架,这是诚实也是保护。
- **查日期防过期**:抓到岗位先看发布 / 报名截止日期;截止日已过、或明显是往届的,标「可能已截止」,**别当在招推**(例:抓到一条截止 3 月的岗,而现在已 5 月 → 提示用户它很可能已关)。
- 别给"版块页"冒充"具体职位"(那是入口不是岗位);要给就给能点进去的真实职位/检索结果链接,或说明这是平台入口让用户自己挑。

---

## 4. 抓不到 / 搜不到怎么办(很常见)

招聘站常有反爬 / 登录墙 / 动态加载,`WebFetch` 可能拿不到正文。这时:
1. **如实说**:"我没能直接抓到具体在招(平台反爬/需登录)。"
2. 给**真实平台入口** + 建议的搜索词,让用户自己点进去搜;
3. 或请用户把看到的**职位链接**发来,我接着帮他拆(转 `jd-analyzer`);
4. 或先只交付**方向**(direction-only)。

> 任何一种都好过编一个假岗位。**没有,就说没有。**

---

## 5. 呈现与筛选

- 按**匹配度 + 可达性**排;明显不合(地点不对、硬卡学历)别塞进来。
- 每个给一句"为什么推给你"(对上你画像的哪点)。
- 数量克制(结果优先):先给 3-5 个最对口的,用户要更多再找。
- 区分"够得着"和"冲一冲",别让用户对着拔高岗海投。

---

## 6. 自检

- [ ] 每个职位 / 公司 / 链接都是这次真搜到的吗?(不是→删)
- [ ] 链接标了抓取时间 + 自行确认提示吗?
- [ ] 抓到的岗位查了发布 / 截止日期吗?过期的标注「可能已截止」了吗?
- [ ] 搜不到的有没有如实说,而不是凑数?
- [ ] 有没有把平台入口页冒充成具体职位?
- [ ] 匹配理由真实、不夸大?
