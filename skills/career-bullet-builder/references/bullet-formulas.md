# Bullet 公式库 · bullet-formulas

简历条目(bullet)的本质:把"我做过的事"压缩成**一行可信、可读、有成果**的话。公式的作用是给这一行一个骨架,逼你写出"动作 + 对象 + 方法 + 结果",而不是罗列职责。

> 选哪个公式:**有真实数字 → XYZ;技术/项目类 → CAR;其余默认 → PAR。** 一段经历可给 1-2 个版本。

---

## 1. PAR(默认)· 情境-行动-结果

> Problem/Project → Action → Result。最通用,适合绝大多数文商社科、运营、行政、课程项目类经历。

**骨架(中文 bullet 通常省略主语"我"):**
```
[在什么情境/为解决什么] + [做了什么动作(强动词起头)] + [带来什么结果]
```

**例:**
- ❌ 弱:`负责一个社会企业的财务分析工作。`
- ✅ PAR:`梳理并分析某社会企业 3 年财务数据,识别 2 项核心运营风险,提出成本控制建议(4 人课程小组)。`
  - 情境=社会企业案例 / 行动=梳理分析+识别风险 / 结果=提出建议;团队语境如实标注。

**适用:** 没有硬核数字、但能说清"做了什么带来什么"的经历(最常见)。

---

## 2. XYZ(有真实数字时)· 成果-量化-方法

> Google 推广的公式:**Accomplished [X], as measured by [Y], by doing [Z]。** 中文顺序更自然:[用 Z 方法] + [达成 X 成果] + [Y 量化]。

**骨架:**
```
[强动词 + 方法/动作 Z] + [达成成果 X] + [用数字 Y 量化]
```

**例:**
- ✅ XYZ:`通过重构数据清洗流程,将月度报表的人工处理时间从 6 小时缩短至 1.5 小时(降低约 75%)。`
- ✅ XYZ:`策划 3 场线下招新活动,带动社团新成员从 40 人增至 90 人。`

**铁律:** XYZ 的数字必须**真实且可解释**。没有真实数字 → 不要硬凑 XYZ,退回 PAR + 量化 fallback(见 `quantification.md`)。继承自上游 `gaps` 的未确认数字**不得**直接写进 XYZ。

---

## 3. CAR(技术 / 项目类)· 挑战-行动-结果

> Challenge → Action → Result。适合技术项目、竞赛、有明确"难点—方案"结构的经历。

**骨架:**
```
[面对什么挑战/难点] + [采取什么技术方案/行动] + [结果(性能/产出)]
```

**例:**
- ✅ CAR:`针对原模型在小样本上过拟合,引入数据增强与早停策略,将验证集准确率从 82% 提升至 89%。`
- ✅ CAR(诚实标注复现):`复现 BERT 情感分类(SST-2),对比 3 组学习率策略,达到 93.1% 验证准确率,与论文 baseline 一致。`[复现性质已标注,不写成"上线系统"]

**适用:** CS/技术岗经历。**注意**:复现、课程项目要如实标注性质,别吹成生产级(见 `no-fabrication.md`)。

---

## 4. STAR 与 bullet 的关系

STAR(Situation-Task-Action-Result)是**面试讲故事**用的完整结构(交给未来的 interview-stories skill)。写进简历 bullet 时把它**压缩**成 PAR / CAR——一行放不下完整 STAR。所以本 skill 不直接用 STAR 出 bullet,只在用户混淆时说明:简历用 PAR/CAR 的压缩版,面试再展开成 STAR。

---

## 5. 长度 / 时态 / 句式规范(中文简历)

- **长度**:每条 1-2 行,约 25-45 字;太长 HR 不读,太短显得单薄。一段经历 2-4 条为宜。
- **人称**:中文简历**省略主语**(不写"我负责…",直接"统筹…")。
- **动词起头**:每条以强动词开头(见 `action-verbs.md`),不要以"负责/参与"这种弱词或名词起头。
- **句式统一**:同一段经历的几条 bullet 句式平行、时态一致、动词不重复。
- **标点**:每条用句号或分号结尾,统一;不要中英文标点混用。

---

## 6. 反模式(看到就改)

| 反模式 | 例子 | 问题 | 改法 |
|---|---|---|---|
| 职责罗列 | "负责日常数据整理工作" | 像 JD 不像成果 | 换成动作+产出:"梳理 X 类数据,建立 Y" |
| 空泛形容词 | "工作认真负责、积极主动" | 不可验证的自我评价 | 删,用具体动作证明 |
| 流水账 | "做了 A,然后 B,又做了 C" | 没有重点和结果 | 按影响力挑 2-3 件,各成一条 |
| 被动/弱开头 | "被安排协助…" | 显得被动无主动性 | 强动词起头 |
| 夸大/造数字 | "提升业务效率 40%"(无来源) | 面试穿帮、背调查不到 | 删数字或换真实量化(见 `quantification.md`) |
| 头衔/贡献夸大 | 团队成果写成个人"主导" | 与真实贡献不符 | 标个人范围,按 evidence 选动词 |

---

## 7. 公式选择速查

```
有真实、可解释的数字?           → XYZ
是技术项目/有明确难点-方案结构?  → CAR
其余(大多数)                    → PAR
拿不准 / 想给用户挑              → 同时给 PAR + 一个量化版,让用户选
```
