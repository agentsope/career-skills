# 简历筛选与关键词 · ats-optimization(国内求职)

国内求职(尤其大中厂校招 / 社招)简历常先过一道**机器 + HR 快筛**:大厂多用招聘系统(如 Moka、北森、i人事或自研)做关键词初筛,HR 平均几秒扫一份。本文件讲怎么让**单条 / 同段 bullet** 既能被机器解析到、又能在快筛里得分。

> 边界:本文件只管"让 bullet 通过筛选并好读"。整份简历的模块编排、长度裁剪、针对岗位的取舍与投递格式,是 `career-resume-tailor` 的活,这里不越界。

---

## 1. 关键词:对齐 JD 的字面词

机器初筛常按**字面**匹配技能词,所以:

- 从目标 JD 提取硬技能 / 岗位词:如 `数据分析`、`Python`、`SQL`、`用户增长`、`财务建模`、`Axure`、`A/B 测试`。
- **用 JD 的原词**,别用近义词替换(机器不一定认"用户拉新"=JD 里的"用户增长")。
- **自然嵌入** bullet,不堆砌:把关键词融进真实动作里。
  - ✅ `用 SQL 提取并分析用户行为数据,定位 2 个流失环节。`(嵌入 SQL、数据分析)
  - ❌ `精通 SQL、Python、数据分析、用户增长、A/B 测试……`(关键词堆砌,HR 反感、也不可信)
- 没做过的技能**绝不堆**进去凑关键词——面试一问就穿帮(见 `no-fabrication.md`)。

---

## 2. 格式陷阱(导致机器解析失败 / 丢分)

很多内容机器**读不到**或读乱,等于白写:

| 别做 | 为什么 | 改用 |
|---|---|---|
| 把关键信息放图片 / 文本框 / 页眉页脚 | 多数解析器读不到 | 正文纯文本 |
| 复杂双栏、表格排版 | 解析后顺序错乱 | 单栏、简单分点 |
| 花哨图标 / 进度条表示技能 | 机器无法识别、也不可信 | 用文字 + 真实例证 |
| 特殊符号 / 艺术字体 | 乱码 | 常见字体、标准项目符号 |
| 文件名随意(如"简历最终版2.pdf") | 不专业、不利归档 | `姓名-岗位-学校.pdf` |

- **优先 PDF**(除非对方明确要 Word);PDF 保版式且多数系统能解析。

---

## 3. 模块与标题(让机器认得出结构)

- 用**标准模块标题**:`教育背景` / `实习经历` / `项目经历` / `技能` / `校园经历`。机器靠这些标题切分内容。
- 别自创花名(如"我的高光时刻")当模块标题——机器归类不了。
- 时间倒序;每段:`组织 + 角色 + 时间`,下面跟 2-4 条 bullet。

---

## 4. 同段 bullet 的快筛友好写法

- **长度**:每条 1-2 行;HR 几秒扫,过长直接跳过。
- **首词承重**:最重要的动作 / 关键词放句首(动词起头),因为视线最先落在行首。
- **影响力排序**:同段内把最相关、最有成果的 bullet 放最前。
- **句式平行 + 动词去重**:见 `action-verbs.md`,读起来整齐、专业。

---

## 5. 自检清单

- [ ] 目标 JD 的核心技能词,有没有用**原词**自然出现在相关 bullet 里?
- [ ] 有没有把关键信息藏在图片 / 表格 / 页眉里?
- [ ] 每条是否动词起头、1-2 行、最相关的在前?
- [ ] 有没有为了凑关键词而写没做过的技能?(有 → 删)
- [ ] 同段动词有没有重复?句式齐不齐?

> 注:关键词对齐依赖目标 JD。若用户还没有明确 JD,提示他"给我目标岗位 / JD,关键词能对得更准"——或先交给 `career-jd-analyzer` 拆解 JD。
