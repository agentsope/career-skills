# 量化方法 · quantification(诚实版)

数字让成果可信、可比——一条带真实数字的 bullet 远胜十句形容词。但本 skill 的底线是:**没有真实数字,绝不编一个出来。** 编造的数字背调查不到、面试解释不了,一旦戳穿不可修复。本文件讲:能量化什么、没数字怎么办、以及怎么帮用户**挖出**真实数字(而不是替他想一个)。

> 铁律:每个写进简历的数字,用户都要能在面试讲清来源。继承自上游的 `gaps` 数字未经用户确认,**一律按"待确认"处理,不写成既成事实**。

---

## 1. 能真实量化的维度

挖数字时,顺着这些维度问用户(大多数人其实有,只是没想到):

| 维度 | 问法 | 例子 |
|---|---|---|
| **规模** | 几个人 / 几个模块 / 多少份 / 多大数据量 / 覆盖多少人 | "4 人小组""清洗 1.2 万条数据""覆盖全院 6 个专业" |
| **频率** | 每周 / 每天做几次 | "每周产出 2 篇""日均处理 50+ 工单" |
| **周期** | 持续多久 / 多久内完成 | "持续 3 个月""2 周内交付" |
| **百分比 / 对比** | 从多少到多少 / 提升降低多少(需真实基线) | "转化率从 3% 提升至 5%""时长缩短约 75%" |
| **金额 / 数量** | 管理多少预算 / 处理多少量 | "管理 5000 元活动预算" |

---

## 2. 没有数字时的 fallback 阶梯(从优到次)

不是每段经历都有漂亮百分比。**没有数字 ≠ 不能写**,按下面阶梯走,绝不用编造补:

**① 技术 / 方法具体化(技术岗首选)**
> 写清技术栈 / 方法 / 步骤,比一个假数字可信得多。
- ✅ `用 Python + pandas 清洗多源数据,统一字段口径并自动化为脚本。`(无数字,但具体可信)

**② 规模替代**
> 用"能数出来"的真实量:人数、模块数、文件数、来源数。
- ✅ `整合 4 个来源的指标,搭建统一周报看板。`

**③ 频率 / 周期替代**
- ✅ `每周复盘运营数据并输出结论,持续一学期。`

**④ 成果定性 + 机制(实在没有量的)**
> 说清"做了什么 → 带来什么",哪怕不量化也要具体。
- ✅ `重构资料归档方式,使小组成员能按主题快速检索,减少重复查找。`

> 顺序原则:技术岗优先①;非技术岗优先②③;④ 兜底。**任何一档都好过编一个数字。**

---

## 3. 怎么帮用户挖数字(而不是替他编)

- 用 §1 的维度**提问**:"这个项目几个人?""数据大概多少条?""做了多久?""有没有前后对比?"
- 给一个**带占位的模板**让他填:`策划 X 场活动,带动成员从 __ 人增至 __ 人` —— 占位符等他填真实值。
- 明确告诉他:**"这些数字只有真实才用,我不会替你编;你能在面试讲清来源的才写进去。"**

---

## 4. 绝不编造(反例)

| ✗ 不能做 | 为什么 |
|---|---|
| 无来源的"提升效率 40%""涨粉 5000" | 凭空捏造,背调 / 面试一问就穿帮 |
| 把"复现模型"写成"上线服务 X 用户" | 性质造假(没部署、没流量) |
| 把"小组一起做"的结果全算成个人数字 | 贡献夸大 |
| 直接采用上游 `gaps` 里"3 年数据"等未确认值 | 未经用户确认,不得当真 |

处理继承的 `gaps`:
- 要么在 bullet 里**留待确认**(给用户看哪里需要他补);
- 要么先输出**不含该数字的保守版**,标注"补了真实数字可升级为 XYZ 版"。

---

## 5. 一条经历的"加数字"演示

- 原始(无数字):`负责社团公众号,涨了一些粉丝。`
- 保守版(先给):`统筹社团公众号运营,策划每周内容排期与 3 次主题活动,带动粉丝稳定增长。` `[PAR · 待补充: 涨粉数字/周期]`
- 用户补充真实数据后 → 升级:`统筹社团公众号运营,3 个月内通过每周排期 + 3 次主题活动,将粉丝从 400 增至 1100(+175%)。` `[XYZ]`

> 同一条,真实数字到位就升级;不到位就停在保守版——永远不替用户填。
