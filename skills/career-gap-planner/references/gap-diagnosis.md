# 差距诊断 · gap-diagnosis

差距 = **目标能力 − 你的现状**。但不是所有差距一样重、一样补得动。诊断的关键是给每个缺口标两件事:**类型**和**可补性**——这决定先补哪个、哪个别浪费时间。

---

## 1. 输入从哪来

- **目标能力**:优先用 `career-jd-analyzer` 的能力模型(`required` / `preferred` / `competencies`);没有就先拆 JD,或用用户给的目标方向。
- **现状**:用 `career-experience-mapper` 的能力清单,或用户自述(学了什么、做过什么、什么水平)。模糊处**直接问**,不脑补用户会什么。

---

## 2. 给每个缺口标「类型」

| 类型 | 是什么 | 例 |
|---|---|---|
| **硬门槛缺** | 不满足就基本被刷 | 学历形式、经验年限、必须证书 / 硬技能 |
| **核心技能缺** | 岗位高频核心、可学 | SQL、Python、某设计工具 |
| **加分项缺** | 有更好、没有也能投 | "有…者优先"里的东西 |
| **软能力缺** | 能力本身有,只是简历没体现 | 沟通 / 协作——常不用"学",用经历证明即可 |

---

## 3. 给每个缺口标「可补性」(最关键)

| 可补性 | 含义 | 处理 |
|---|---|---|
| **可补(短期)** | 几周-几月能到能用 | 进补强计划,排优先级 |
| **难补(长期)** | 需数月-数年积累 | 评估时间够不够;不够则考虑绕 |
| **基本不可补(短期)** | 形式硬卡,补不了 | 如实说 + 给绕过策略,别耗 |

> 典型"基本不可补":统招 / 全日制学历形式、已固定的应届身份、硬性年限。**这些要第一时间如实告诉用户**,免得他在补不上的事上空耗。

---

## 4. 排优先级

```
① 卡硬门槛 且 可补       → 最先补(不补就进不去)
② 核心技能缺            → 次之(决定能不能干好、面试能不能过)
③ 加分项缺              → 有余力再补
—— 软能力缺            → 多数不用"学",用经历证明(回指 mapper/bullet)
—— 基本不可补          → 单列,给绕过策略,不排进学习计划
```

---

## 5. 输出(给 Step 4 用)

一张差距表:

| 缺口 | 类型 | 可补性 | 优先级 |
|---|---|---|---|
| SQL | 核心技能 | 可补(~3-4周) | 高 |
| 数据分析项目经历 | 核心/加分 | 可补(~2周) | 高 |
| 统招本科 | 硬门槛 | 基本不可补 | 单列·绕 |
| 3 年经验 | 硬门槛 | 难补 | 看岗位是否真卡(实习/应届常不卡) |

> 注意:同一条"要求"在不同岗位严格度不同(如"X 年经验"对实习岗往往不卡)。结合 `jd-analyzer` 的硬性/软性判断,别把软性当硬卡吓退用户。
