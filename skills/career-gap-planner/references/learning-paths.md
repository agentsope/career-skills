# 学习路径 · learning-paths

把"补 X 能力"变成**可执行、可验证、有现实时间**的路径。原则:不是"学好 Python",而是"用[真实资源]做到[能验证的里程碑],产出[能写进简历的东西]"。

---

## 1. 每个缺口拆成四件事

```
目标程度 → 路径(学什么 + 做什么)→ 里程碑(可验证)→ 现实时间
```

- **目标程度**:补到"能干岗位要求的活"即可,不求精通。明确终点(如"能独立写多表 SQL 查询并出一份分析"),别开放式"学好"。
- **路径**:基础(资源)→ 实践(项目)。学完立刻用,别只看课。
- **里程碑**:可验证的产出 / 能力点(做出 X、能独立完成 Y),不是"学完了"。
- **现实时间**:给区间 + 说明依赖每周投入。**不承诺"X 天精通"。**

---

## 2. 终点必须是"能写进简历的真实项目"(闭环)

补强不是为了"学过",是为了**多一段能写进简历的真实经历**。所以每条路径的终点设一个**真实产出**:

- 学 SQL → 用公开数据集做一份真实分析 → 这就是一条新简历经历。
- 学 Python 爬虫 → 做一个真实的小工具 / 数据集 → 写进项目经历。
- 补设计 → 完成 1-2 个真实作品进作品集。

> 做完把成果回流给 `career-experience-mapper`(萃取能力)→ `career-bullet-builder`(写成 bullet)。学→做→写进简历,闭环。

---

## 3. 现实的时间预期(别画饼)

- 给**区间**,并写清前提(如"每周投入 ~10 小时,约 3-4 周到能用")。
- 区分"入门能用"和"熟练 / 精通"——简历和实习通常只需"能用 + 有项目证明"。
- 投入不够就把周期拉长,**不缩短承诺**。
- 长期能力(如系统的工程能力、领域 know-how)如实说"这是长期积累",别假装速成。

---

## 4. 排序与节奏

- 先补**卡门槛且能最快见效**的(性价比最高),让用户尽快够得着投递线。
- 一次别铺太多;**2-3 个并行上限**,否则都补不动(也呼应"结果优先、别一长串")。
- 能"边做项目边补"的,优先用项目带动学习(比纯刷课高效)。

---

## 5. 示例(缺 SQL)

```
缺口:SQL(核心门槛,可补)
目标程度:能独立写多表查询、聚合、子查询,并完成一份数据分析
路径:基础语法与查询(资源见 resource-finding)→ 拿一个公开数据集做端到端分析
里程碑:独立产出一份含 SQL 取数 + 结论的分析报告
现实时间:每周 ~10h,约 3-4 周到"能用 + 有作品"
产出回流:这份分析 → 写成简历项目经历
```
